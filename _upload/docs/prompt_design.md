# 系统提示词设计说明（成员 B）

> 交付物 #3：系统提示词（`prompts/system_prompt.txt`）+ 本设计 rationale
> 目标：用提示词约束，确保 RAG 行为约束 R1~R6 **全部生效**。

---

## 1. 设计原则

1. **强制优先于自觉**：R1（先检索）不靠模型“自觉”，而在**代码层**先 `knowledge_search` 再生成（见 `qa_system.py` 的 `ask()`）。提示词只负责约束“内容怎么写”，流程由代码兜底，双保险。
2. **可核查、可追责**：每条要求都对应一个可在测试报告里逐条验证的行为（对应 `docs/test_report.docx`）。
3. **最小必要信息**：提示词只放“行为规则 + 引用格式 + 语言风格”，检索到的教材内容通过 `{retrieved_context}` 占位符在每次问答时动态注入，避免把整本教材塞进系统提示词（省 token、防泄露越界）。

---

## 2. 五段结构 ↔ R1~R6 映射

| 段落 | 约束的目标 | 对应编号 | 关键话术 |
|---|---|---|---|
| 第一段·RAG 工作流 | 先检索后回答 | **R1** | “收到任何课程问题后，必须**先调用** knowledge_search，绝不可凭记忆直接作答” |
| 第二段·知识边界 | 只用教材 | **R2** | “答案中的全部事实性内容必须来自检索片段；不得使用训练语料补充” |
| 第三段·引用规范 | 页码引用 | **R3** | “每个事实性陈述后必须紧跟【教材 p.XX】；页码只能引用检索结果中实际出现的” |
| 第四段·语言风格 | 简单中文+术语 | **R4** | “通俗易懂中文；关键术语保留英文原文，如 process / thread / deadlock” |
| 第五段·版权与诚实 | 版权+诚实 | **R5 / R6** | “禁止连续超过 3 句原文；未覆盖须如实说明‘未检索到相关教材内容’” |

---

## 3. 关键设计决策与 rationale

### 3.1 为什么“检索先于回答”放在代码而非仅提示词
参考案例（CN-Tutor）用 `toolOrder` 强制工具顺序。本方案没有引入重框架，而是在 `ask()` 中**先 `retrieve()` 后 `call_llm()`**，从根本上保证 R1，无论底层模型是否支持 function calling。提示词第一段再对用户/模型重申该规则，形成“代码 + 提示词”双重约束。

### 3.2 引用占位符 `{retrieved_context}`
每次问答时把 `knowledge_search` 结果格式化为：
```
[【教材 p.XX】｜《章节名》] 片段正文
```
注入到提示词末尾，明确要求模型“基于上方检索上下文作答”。这样模型看到的页码与原文一一对应，R3 可落实；同时把知识严格限制在注入片段内，落实 R2。

### 3.3 引用格式严格化（防幻觉页码）
R3 要求页码“只能引用检索结果中实际出现的”，因此提示词明确禁止臆造页码；检索工具 `retrieval.py` 返回的 `citation` 字段即来自数据库真实页码，模型只需照搬，杜绝编造页码。

### 3.4 版权红线（R6）
教材为受版权保护材料。提示词设定“连续 >3 句原文即违规”，并以“短句引用 + 转述”为正道；无 Key 退化模式（`compose_answer`）仅取片段前 3 句并转述，从代码上保证不越线。

### 3.5 诚实兜底（R5）
当 `knowledge_search` 返回空，提示词第五段要求输出“未检索到相关教材内容”，不推测。测试报告中用“超纲问题”（如 Kafka 集群配置）专门验证此条。

---

## 4. 回答格式约定（对应评分“回答格式 3 分”）

- 每条事实后紧跟 `【教材 p.XX】`；
- 多片段时分别标注，不合并；
- 术语中英对照、分点短句；
- 未覆盖 → 明确告知“未找到”。

---

## 5. 可演进性

提示词与检索解耦：更换教材只需重跑 `build_kb.py`，提示词几乎不变（仅改书名）；同一套提示词可配合向量检索（拓展挑战“混合检索”）复用。
